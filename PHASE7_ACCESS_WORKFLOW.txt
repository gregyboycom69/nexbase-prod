This is the most important phase. Make NexBase work exactly like 
MS Access but better and cloud-based.

The MS Access workflow is:
1. First design your TABLES (define fields and data types)
2. Then create QUERIES (filter/join table data)
3. Then design FORMS (visual interface bound to a table or query)
4. Forms can have SUBFORMS (another form embedded inside)
5. Everything is connected - form saves to table, query filters table data

=== UNDERSTANDING THE FULL STRUCTURE ===

In MS Access:
- Tables = where data lives (like Supabase tables)
- Queries = saved SQL/filter definitions
- Forms = visual designer bound to a table
- Reports = printable layouts (Phase 8)
- Macros = automation (already built)

In NexBase the studio should have these TABS at the top:
Tables | Queries | Forms | Reports | Macros

Currently we only have the canvas (Forms tab).
We need to add Tables and Queries properly.

SQL to store table definitions:
CREATE TABLE IF NOT EXISTS workspace_tables (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  slug TEXT NOT NULL,
  fields JSONB DEFAULT '[]',
  created_at TIMESTAMPTZ DEFAULT NOW()
);
ALTER TABLE workspace_tables ENABLE ROW LEVEL SECURITY;
CREATE POLICY owner_tables ON workspace_tables FOR ALL USING (
  workspace_id IN (SELECT id FROM workspaces WHERE owner_id = auth.uid())
);

Each field stored in JSONB array like:
[
  { "name": "id", "type": "AutoNumber", "required": true, "primaryKey": true },
  { "name": "name", "type": "Short Text", "required": true, "maxLength": 255, "caption": "Customer Name" },
  { "name": "status", "type": "Choice", "options": ["Active","Inactive","Trial"], "default": "Active" },
  { "name": "revenue", "type": "Currency", "default": 0 }
]

Each column in the grid is one field in the query result:

- Show: checkbox (include in results)
- Criteria: text input (e.g. "USA" or ">100" or "Like 'A*'")
- Or: additional criteria rows for OR conditions

- Run (execute the query, show results in datasheet)
- Save (save query definition)
- Query Type: Select | Make Table | Append | Update | Delete
- Show Table (add another table to query)
- Totals (show Group By, Sum, Avg, Count etc)
- Top Values input (return only top N records)

When Run is clicked:
- Build the query from the QBE grid
- Execute against app_data in Supabase
- Show results in a datasheet view below
- Show record count

Query results datasheet:
- Scrollable grid with column headers
- Alternating row colors
- Click row to select
- Export to CSV button
- Copy to clipboard button

This is the most important part.

"What is this form based on?"
Options:
- A Table (pick from dropdown of workspace tables)
- A Query (pick from dropdown of saved queries)

- The Record Source property is set
- In properties panel a "Add All Fields" button appears
- Clicking it auto-generates controls for each field:

  - Long Text → TextArea (new control type)
  - Number, Decimal, Currency → NumberBox
  - Date/Time → DatePicker
  - Yes/No → CheckBox
  - Choice → ComboBox (with the options from field definition)
  - Image, File → ImageViewer

- Controls are laid out automatically in a 2-column grid
- User can then move/resize them as needed

Show in Properties panel when no control selected (form properties):

- Filter: (criteria to limit records shown)
- Order By: (field to sort by)
- Allow Edits: yes/no
- Allow Additions: yes/no
- Allow Deletions: yes/no
- Default View: Single Form / Continuous Forms / Datasheet
- Navigation Buttons: yes/no
- Record Selectors: yes/no
- Scroll Bars: both/neither/horizontal/vertical

Control Properties when bound control selected:

- Input Mask (for text fields)
- Validation Rule
- Validation Text
- Status Bar Text (help text shown at bottom)

=== TASK 5 - SUBFORM CONTROL ===

The Subform control type should be fully functional.

When user drops a Subform control onto the canvas:
Properties panel shows:
- Source Form: dropdown of other forms in this workspace
- Link Master Fields: field in parent form to link on
- Link Child Fields: field in subform to match
- Allow Edits: yes/no
- Allow Additions: yes/no

How it works:
- Parent form is bound to Customers table
- Subform is bound to Orders table
- Link Master = Customers.id
- Link Child = Orders.customer_id
- So when user views Customer #3, subform shows only orders for customer #3

In design view: show a placeholder box with "Subform: [source]" label
In preview/published: show the actual subform with filtered data

=== TASK 6 - FORM TYPES ===

When creating a new form let user choose the form type:

1. Single Form (default)
   Shows one record at a time
   Navigation buttons at bottom
   Fields laid out as designed

2. Continuous Forms
   Shows multiple records stacked vertically
   Each record shows same layout
   Scroll to see more records
   Click a record to select/edit it

3. Datasheet Form
   Shows records in spreadsheet grid
   Click cell to edit
   Like MS Access datasheet view
   Has Add Row at bottom

4. Split Form
   Top half: Single form view of selected record
   Bottom half: Datasheet of all records
   Click row in datasheet to navigate form

5. Dialog / Popup Form
   Opens as a modal over the main form
   Has OK and Cancel buttons
   Used for data entry popups

6. Wizard Form
   Multi-step form with Next/Previous buttons
   Each page of wizard = one step
   Progress indicator at top
   Finish button on last step

Store form type in forms table:
ALTER TABLE pages ADD COLUMN IF NOT EXISTS form_type TEXT DEFAULT 'single';

ALTER TABLE pages ADD COLUMN IF NOT EXISTS form_filter TEXT;
